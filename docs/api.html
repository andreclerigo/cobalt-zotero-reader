Bridge API

The versioned HTTP contract used by the Kobo. It is read-only with respect to Zotero; POST starts derived conversion work only.

Authentication

GET /v1/health is public. Every other route requires Authorization: Bearer <bridge token>. Do not place the token in a query string. Keys in paths are bounded alphanumeric identifiers and every item route revalidates membership in at least one allowlisted collection.

Routes

Method and pathPurpose
GET /v1/healthProcess health. Returns {"status":"ok"}.
GET /v1/collectionsCollections in the deployment allowlist.
GET /v1/collections/{key}/snapshot?limit=500Bounded newest-first item summaries for one allowed collection.
GET /v1/items/{key}Normalized metadata and stored-PDF availability.
POST /v1/items/{key}/conversionStart or coalesce conversion of the stored PDF.
GET /v1/items/{key}/conversionRead current conversion state.
GET /v1/items/{key}/documentRead sanitized, bounded HTML after conversion is ready.
GET /v1/items/{key}/figures/{name}Read one derived PNG or JPEG referenced by the document.

Conversion states

  • missing_pdf — no stored PDF is available.
  • queued — accepted by the bounded local queue.
  • running — Docling conversion is active.
  • ready — document HTML is available.
  • failed — conversion ended with a safe user-facing message.

Content limits

  • Snapshots are capped at 500 summaries.
  • Normalized HTML is capped at 768 KiB and truncates only between blocks with an explicit notice.
  • At most 64 referenced figures are published; each must fit Cobalt's 4 MiB picture limit.
  • The service downloads only a stored Zotero attachment and uploads PDF bytes—not a URL—to Docling.

Operational behavior

The bridge honors Zotero pagination and backoff headers, limits Zotero and conversion concurrency, coalesces duplicate jobs, publishes cache entries atomically, and deletes job-scoped source PDFs after success, failure, timeout, or restart recovery. Persistent state contains derived HTML and figures only. Document responses include Cache-Control: no-transform so proxies cannot inject browser-only scripts into sanitized reader HTML.

New routes or broader credential use require matching Cobalt policy and negative-test updates.
