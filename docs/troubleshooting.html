Troubleshooting

Identify whether the failure is on the Kobo, at Zotero, or in the optional conversion service before changing configuration.

“Permission needed”

The runtime does not have the named secret. Re-run the interactive command for zotero, or for zotero-bridge when using conversion mode. A key installed under a different name is intentionally not accepted.

No collections appear

Confirm the number entered in the app is the numeric Zotero user ID shown beside the API key. Verify the dedicated key has read access to the personal library. The app reads user collections, not group libraries or saved searches.

I cannot switch collections

Open the folder-shaped Collections action in the feed header. It refreshes the collection list from Zotero. If Zotero is offline, the current collection and its cached snapshot remain available; collection discovery itself needs a connection.

Metadata appears but no full text opens

The item must have a PDF stored in Zotero. A linked local file, DOI, publisher page, or URL attachment is not downloaded. Sync the stored attachment to Zotero, refresh the reader, then open the paper again. Direct mode also depends on Zotero having indexed the PDF text.

“The conversion service could not be reached”

  1. Check that the service survives reboots: docker compose ps.
  2. From another machine, request https://your-host/v1/health. The site root returning 404 is normal; the API starts at /v1/.
  3. Confirm the Cobalt package was built with exactly that bare HTTPS origin.
  4. Confirm DNS and TLS work from the Kobo's current Wi-Fi, not only from the host itself.

Conversion stays queued or running

Inspect docker compose ps and the bridge and Docling logs. The first conversion includes model loading and can take several minutes. Do not expose Docling directly or raise time and memory limits independently; the bridge and Docling limits must remain synchronized.

A reading-position save is pending

Use the visible Retry position action before opening another paper. The app blocks the next paper so a failed save cannot silently attach one paper's position or annotations to another. If storage is full, remove an offline document and retry.
