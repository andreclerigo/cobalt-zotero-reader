Self-host the bridge

A single-user Docker Compose deployment for richer conversion of PDFs already stored in Zotero.

Not GitHub Pages: Pages hosts this documentation, but cannot run FastAPI, Docling, background jobs, persistent cache, or secrets.

Host requirements

  • A 64-bit Linux host with Docker Engine and Compose, persistent storage, public DNS, and inbound HTTPS.
  • A dedicated read-only Zotero key, numeric user ID, and at least one allowed collection key.
  • An encrypted cache volume owned by uid/gid 10001:10001 with mode 0700.
  • Enough memory for Docling. A Raspberry Pi 5 with 8 GiB and SSD is a practical low-volume baseline; a VPS is usually simpler.

Configure

cd services/zotero-conversion-bridge
cp .env.example .env
chmod 600 .env
openssl rand -hex 32  # bridge token
openssl rand -hex 32  # separate Docling token

Fill every blank field. ALLOWED_COLLECTION_KEYS accepts comma-separated collection keys, so one deployment can expose several collections from the same user library. Use the same Docling token for DOCLING_API_KEY and DOCLING_SERVE_API_KEY.

Validate and start

docker compose config
docker compose up --build -d
docker compose ps
curl --fail https://papers.example.com/v1/health

Replace papers.example.com with the exact host written in .env.

Only Caddy publishes ports. The bridge and Docling networks are internal, and Docling is not directly reachable from the internet. The first real conversion is slower because Docling loads its models lazily.

Bind a Cobalt build to the service

ZOTERO_READER_BRIDGE_ORIGIN=https://papers.example.com \
  cargo run -p kobo-cli -- package
cargo run -p kobo-cli -- secret set zotero-bridge --device <address>

The origin must be bare HTTPS with no path, user-info, alternate port, or trailing slash. The device token is separate from the Zotero key.

Deployment acceptance check

  1. Confirm an unauthenticated API request is rejected and Docling has no public port.
  2. Using an allowlisted real item with a stored PDF, start one conversion and poll until ready.
  3. Open the HTML document and at least one figure on the Kobo.
  4. Restart Compose and confirm the cached document remains readable.
  5. Revoke test tokens after staging if they are not the intended production credentials.

State, backup, and rollback

Source PDFs are temporary and deleted after conversion. Derived HTML and figures are cached for 30 days after last access under a 10 GiB quota. Preserve Caddy's volume during ordinary redeployments; the derived and Docling model caches are reproducible. Roll back by revoking both tokens, stopping Compose, purging derived cache if needed, and deploying the previous Cobalt package. Zotero needs no data restore because the integration is read-only.

Who should not share this instance?

This bridge has one Zotero identity, one bearer token, one allowlist, and one cache namespace. It is suitable for one owner or a trusted household. A public community service needs per-user authentication, isolated credentials and cache, quotas, abuse controls, and shared job coordination; v1 deliberately does not claim those properties.

Operational details and exact environment variables remain in the bridge README in the source repository.
